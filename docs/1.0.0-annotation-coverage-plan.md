# 1.0.0 annotation coverage plan

The ROADMAP's 1.0.0 entry commits this repository to annotation coverage. This note defines that
commitment in two units, the annotation and the attribute. It records what 0.11.0 delivered and
places what remains across 0.12.0, 0.13.0 and the 1.0.0 cut. It also lists what the SDK must
deprecate for removal before its 1.0.0-RC, because this repository gives it no destination.

**Where this applies.** It applies to the annotations under `eu.exeris.sdk.annotation`, nested
annotations included, at the SDK version the BOM pins (0.13.3 today). It does not cover AST record
components that no annotation fills. Those belong to the SDK's record-growth rule, ADR-042 reader
parity and `exeris-sdk-tck`. It does not judge whether emitted output is correct; the generated
tests (ADR-058) do that. It says nothing about kernel features or `@exeris/ui-kit`.

**The trade-off.** Most of what this plan closes is closed by deletion, not emission. A WITHDRAW row
takes a line from authors who used the attribute as documentation of intent, such as the Stellar and
budgetHQ corpora. They get a deprecation warning and lose the line at 1.0. The alternative was to
freeze such attributes with no effect. That keeps every source compiling and promises, for the whole
1.x line, behaviour nothing produces. The guard has a running cost too: every SDK bump fails the
build until its new attributes are given a disposition.

## Why 1.0.0 cannot leave a frozen attribute without effect

- **Every SDK annotation is `@Retention(SOURCE)`.** The processor and the generators are its only
  consumer. An attribute that reaches no generator has no effect at any tier.
- **No Tier-2 capability consumes an annotation.** No `exeris-caps-*` repository reads
  `DomainMetadata` or runs a processor. A capability assignment leaves an attribute with no
  consumer, so it is not coverage.
- **The SDK freezes what it declares.** The SDK stability matrix (`exeris-sdk`
  `docs/stability-matrix.md`) says a `RESERVED` annotation is frozen as declared unless the kernel
  tier of its contract keeps it out (ADR-072 obligation 29). After 1.0.0 an attribute can be
  deprecated but not removed before 2.0. Whatever this repository cannot give a destination must be
  deprecated for removal before the SDK's 1.0.0-RC, or it ships frozen with no effect.

## Dispositions

| Disposition | Meaning | Who closes it |
| --- | --- | --- |
| **EMIT** | The attribute or annotation reaches emitted output on at least one side. Its `INERT_ATTRIBUTES`, `INERT_ANNOTATIONS` or `UNREAD_NOTES` entry and its `RESERVED` row in `contract-coverage.ts` are deleted in the same change. | this repository |
| **WITHDRAW** | The SDK deprecates it for removal before 1.0.0-RC. Tooling keeps the strict-mode warning until the SDK 1.0 pin removes it. | exeris-sdk, on the ask in *SDK withdrawal list* |
| **OUTSIDE FREEZE** | Its destination is a kernel contract that is not `stable` at the kernel's 1.0. The SDK lists it as Preview, as it already does for `@Schedule` and `@Channel`. It is promoted when the kernel half is final. | exeris-sdk, on the ask in *Outside-freeze asks* |

Surfaces the SDK has already marked `forRemoval` need no disposition from here. Their registry
entries go with the SDK 1.0 pin (#443, #445).

## What the SDK has already decided

These are not re-asked. Sources: SDK `MIGRATION-0.x-to-1.0.md` §1 and §2, and `docs/stability-matrix.md`.

- **Removed at 1.0:**
  - `@Validation.required` and `validateOn`.
  - `@ExerisDomain.tenantScoped`, `apiVersion` and `roles`; `@Action.roles`.
  - `@Encrypted`, `@RowLevelSecurity` and every encryption attribute.
  - 76 `@Saga` and 67 `@SagaStep` elements, among them `@SagaStep.retries`, `waitForAll`, `failFast`,
    `dependsOn`, `condition`, `InputMapping`, `OutputMapping`, `CommandHeader` and `MetricTag`.
  - 29 `@GraphEdge` attributes with `ComputedProperty`.
  - The six `@QueryParam` attributes.
- **Preview:** `@Schedule`, `@Channel`, and the `@GraphEdge` kernel-model attributes (`direction`,
  `bidirectional`, `inverseType`, `weighted`, `weightField`, `staticWeight`, `properties`,
  `propertyMappings`, `staticProperties`, `upsert`).
- **Frozen, reserved by name:** `@Derived`, `@Rule`, `@SagaTransition`, `@EventHandler`, the
  operational attributes of `@Projection`, `@Action.realTimeUpdates`, the system markers,
  `@ExerisDomain.validationMode`, and the five `@InternalApi` attributes (§4).
- **`@UI` stays through 1.x.** It is deprecated in the 1.x minor that lands the ADR-047 leaf facet
  and removed at 2.0.

Three of the frozen-reserved rulings are re-asked below with evidence: `validationMode`,
`realTimeUpdates` and the `@InternalApi` attributes. A reserved surface frozen with no emitter is
the outcome this plan exists to prevent.

## SDK withdrawal list (deprecate for removal before 1.0.0-RC)

Filed as exeris-systems/exeris-sdk#278 on 2026-11-08, each entry checked against the SDK `v0.13.3`
sources and the kernel `v0.13.1` `EventTypeSpec`. G1 re-checks the list against the catalogue.

- **`@DomainEvent`, 42 attributes with no kernel destination:**
  - `version`, `tags`, `partitionKey`, `exchange`, `routingKey`, `priority`, `ttlMs`, `mandatory`,
    `includeSnapshot`, `payloadTransformer`, `maxPayloadSize`.
  - `schemaFormat`, `schemaNamespace`, `schemaSubject`, `compatibility`, `registerSchema`,
    `schemaDoc`, and `headers` with `DomainEvent.Header`.
  - `includeTraceContext`, `includeTenantContext`, `includeUserContext`, `includeCausation`,
    `includeTimestamps`, `includeSource`.
  - `retentionDays`, `archiveAfterDays`, `compressAfterDays`, `storeInEventStore`, `consumers`,
    `expectedProcessingTimeMs`, `requiresIdempotency`, `processingGuarantee`.
  - `useOutbox` (the outbox is what `persistent` selects), `outboxTable`, `outboxAggregation`,
    `outboxAggregationWindowSeconds`.
  - `emitMetrics`, `logLevel`, `alertOnFailure`, `traceSampleRate`, `disableInTests`,
    `mockConsumer`.

  The kernel's `EventTypeSpec` carries `name`, `ordinal`, `persistent`, `ordered` and `topic`. This is
  the same ruling the SDK applied to the `@Saga` monitoring and dispatch families in 0.13.0.
- **`@ExerisDomain`:** `graphqlApi` (no GraphQL surface in the kernel or either emitter);
  `validationMode` (honouring its `STRICT` default would fail every build without a system-field
  marker); `cacheable`, `cacheTtl`, `cacheRegion` (no cache contract); `fullTextSearch`,
  `searchConfig` (the list route searches `@Field(searchable)`, ADR-096 Amendment 4); `restApi` and
  `internalClient` (both emitters emit REST for every entity).
- **`@Action.path`.** The route is `{domainPath}/{id}/actions/{kebab-action-name}` on both sides. The
  SDK's own Javadoc already calls the attribute's future open. Also `httpMethod`, `async` and
  `realTimeUpdates` if W0-4 confirms.
- **`@TenantId.autoPopulate`, `exposeInApi`, `validateOnMutation`.** Every value other than the
  default would switch off the isolation the generated repository enforces.
- **`@PrimaryKey.generated`, `sequenceName`, and `Strategy.SEQUENCE`, `IDENTITY`, `NONE`** (W0-10).
- **`@AuditCreatedBy.expression`, `@AuditUpdatedBy.expression`.** No kernel contract evaluates an
  expression. This is the SDK's ruling on the `@Saga` expressions.
- **`@Field.group`.** It duplicates `@UIGroup`, which reaches output.
- **`@NavMenu.roles`.** Role-based access has no SDK declaration at 1.0 (the SDK's ruling on
  `@Action.roles`).
- **`@InternalApi.consumers`, `rateLimit`, `requireMtls`, `timeout`, `documented`** (W0-3).
- **`@SagaStep.service`, `command`**, after the SDK gives each a default (W0-5).
- Conditional: the `@Saga` compensation attributes W0-6 finds no kernel field for; the

## The cut — what 1.0.0 adds

- **Criterion.** The G1 test passes against the SDK 1.0.0 catalogue. It has no `OPEN` rows and no
  `SDK_REMOVED` rows. `OUTSIDE_FREEZE` rows match the SDK's Preview list. `REFUSED` rows are
  `@Schedule` alone. `EXCEPTION` rows are the founder-approved list, each citing its SDK ruling.
  `contract-coverage.ts` still reports 0 `GAP`.
- **Why a test and not a count.** The ROADMAP's hand count said 51 on 2026-08-18. The 0.11.0 plan
  counted 54 types. The two numbers measure different sets, and neither covers attributes. The
  catalogue test reads the same file the SDK publishes, so it moves with the pin.
- **What the test cannot prove.** An `EMITTED` row proves a generator is named, not that a
  non-default value changes output. Every EMIT row therefore adds a processor-compiled fixture that
  sets the attribute to a non-default value. Fixtures built with `DomainMetadata.builder` cannot see
  an attribute the processor never reads.
- **Sequence.** File the withdrawal and outside-freeze asks before the SDK 1.0.0-RC, then 0.12.0 and
  0.13.0 as above. Then SDK 1.0.0 final, with no SNAPSHOT at the cut. Then the 1.0.0 release PR on
  the existing cut sequence.
