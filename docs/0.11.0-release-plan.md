# 0.11.0 release plan

0.11.0 has no date; its scope closes it. **Bring the SDK annotations that SDK 0.13 reads back to
emitted output: `@PrimaryKey`, `@GraphProperty`, `@UIGroup`, `@Blob`, `@QueryParam`, `@NavMenu`,
`@Tab` and the route-policy data of `@RouteAccess`; bind `exeris-sdk-tck` and close every facet it
checks; and close the correctness, coverage and hygiene debts listed below.** Each extraction needs
an SDK 0.13 half, so this is the release that pins SDK 0.13. The
[ROADMAP](../ROADMAP.md) "0.11.0" section keeps the checklist and points here. This note holds the
order, the gate on each item and the Java/TS pairing, in the shape of the
[0.10.0 plan](0.10.0-release-plan.md).

**Pins.** SDK 0.13.0 and kernel 0.13.0, both final on Maven Central (#447). SDK 0.13.0 carries the
`-io` reader half for `@PrimaryKey`, `@GraphProperty`, `@UIGroup` and `@Blob` (exeris-sdk#187), the
carriers `ActionParamMetadata.bindingSource`/`queryKey`, `DomainMetadata.navMenu` and
`UIMetadata.tabs` (exeris-sdk#186), and the reader for `routeAccess` and `permissions`
(exeris-sdk#161). It carries no reader half for `@Channel`, so J4 and S3 are in 0.12.0 (*Not in
0.11.0*). Kernel 0.13.0 asks an `HttpRoutePolicy` about a path without its query string and about a
`HEAD` as its `GET`, and removes nothing the emitted code calls; `spi.storage.blob` is stable in it.
A row needing an SDK 0.13.x patch enters only if the patch is final on Central before the cut. No
cross-repo SNAPSHOT at the cut (Versioning policy).

**Shapes SDK 0.13 reads.** The reader half fixes the form of each component, and the processor
writes that form (ADR-042 amendment, exeris-sdk#187):

| Component | Form the processor writes | Row |
| --- | --- | --- |
| `UIGroupMetadata.gridSpan` | always `12`; `@UIGroup.columns` is not mapped onto it | J2 |
| `GraphPropertyMetadata.field` | the declaring field's name | J2 |
| `GraphEdgeMetadata` | the eight components SDK 0.13 adds; the processor accepts a repeated edge (#437) | J2 |
| `ActionMetadata.resultType` | the `TypeMirror.toString()` form (#436) | J8 |
| `SagaMetadata.trigger` and the compensation components | the trigger by constant name (#432), and the six compensation components | J7 |
| `GraphMetadata.queries` | `null` (`@GraphQuery` is not in 0.11.0) | J2 |
| `FieldMetadata.inCreate` / `inUpdate` | both keys on every field, `false` included; the loaders' rule for an absent key is #401 | A1 |
| `SchemaVersion` | `0.13.0`; metadata from a 0.12 processor is schema skew | A1 |
| `pluralName()` | a vowel before a trailing `y`, in either case, takes a plain `s` (#431) | A1 |

## Why most rows wait on the SDK

Two different SDK halves gate these annotations, and every extraction needs at least one:

- **A carrier** — an AST component the processor can write. SDK 0.13 adds those for `@QueryParam`,
  `@NavMenu` and `@Tab` (exeris-sdk#186).
- **The reader half** — ADR-042 requires the SDK's `-io` `SourceModelReader` to read what the
  processor writes, in the same release, or the two producers diverge and a round-trip caller
  reads the dropped facet as a user edit. SDK 0.13 reads `@PrimaryKey`, `@GraphProperty`,
  `@UIGroup` and `@Blob` (exeris-sdk#187), and `routeAccess` and `permissions` (exeris-sdk#161).

So no row writes its component until the SDK pin carries both halves. SDK 0.13.0 carries them for
every row below; `@Channel` alone has neither reader half nor stable kernel SPI. TS wave S6 is outside
this rule: it closes `@View` page gaps that 0.10.0 wave S6 left open, and only its SEO stretch
item (#412) waits on the SDK.

**The measure.** `exeris-sdk-tck` 0.13 checks a producer against the SDK's corpus, facet by facet;
a binding names the facets it does not support in `unsupportedFacets()`. Each extraction row removes
its facet from that list in the same change, and a test holds the list to shrinking only. The SDK
0.13.0 corpus declares no primary-key field, which the processor refuses (EXT-PROC-1015), so the
binding waits on a 0.13.x corpus patch (exeris-sdk#249).

**Gate vocabulary:** as in the 0.10.0 plan — **none**, **RFC/ADR** (number reserved in
`exeris-docs/adr-index.md` and on `main` before the content), **upstream** (a kernel or SDK issue;
the row enters only if that half is final before the cut).

## Wave 0 — decisions

- [ ] **`@Blob` route shape** — RFC, then ADR: the upload and download routes, how a `@Blob` field
      appears in the entity DTO, the refusal on a `dataScope = GLOBAL` entity, and the
      `storage.blob.provider` key.
- [ ] **Generated integration tests (#408)** — an ADR-058 amendment: an opt-in `*IT` channel run by
      Failsafe from its own source root, booting the emitted application on H2 for `GLOBAL`
      entities, and how the test binds a principal. PostgreSQL and tenant scopes are 0.12.0.
- [ ] **List route search (#365)** — an ADR-096 amendment: server-side search on the list route,
      its matching semantics, and the relationship picker that uses it.
- [ ] **An `@Action` parameter without `@ActionParam` (#422)** — the build refuses it; recorded as
      an ADR-044 amendment.
- [ ] **Graph property encoding** — a kernel ask. `GraphSession.upsertNode` takes an encoded
      `LoanedBuffer`, the SPI names no encoding ("e.g. MessagePack or raw JSON"), and the Community
      driver decodes UTF-8 JSON. Emitted code must not bind to one driver's choice, so the SPI
      states the encoding, or the J2 PR records the assumption (UTF-8 JSON) and the reason.
- [ ] **`customBlocks` source of truth (#417)** — stretch, with S6.
- [ ] **`@GraphQuery`** — a decision between the kernel and the SDK (see *Not in 0.11.0*).

## Annotation coverage

Of the 54 SDK annotation types, 22 reach no emitted output on either side: 19 the processor never
reads, and three it reads without any generator emitting from them (`@EventSourced`, `@InternalApi`,
`@RouteAccess`). `EXTRACTED_ANNOTATIONS`, `INERT_ANNOTATIONS` and `UNREAD_NOTES` in
`ExerisDomainProcessor`, and `contract-coverage.ts` on the TS side, are the authority for those
counts. The table covers eleven of the 22: seven are placed in 0.11.0 and four are not.

| Annotation | SDK carrier | Kernel contract | Wave | Waits on |
| --- | --- | --- | --- | --- |
| `@PrimaryKey` | `SystemFieldsMetadata.primaryKeyField` | none needed | J1 | — |
| `@GraphProperty` | `GraphMetadata.properties` | `GraphSession.upsertNode` | J2 | the encoding |
| `@UIGroup` | `UIMetadata.groups` | none needed | J2 + S1 | — |
| `@Blob` | `FieldMetadata.blob` | `storage` subsystem, `BLOB_STORE` | J3 + S2 | RFC/ADR |
| `@Channel` | `DomainMetadata.channel` | `WebSocketProvider` (kernel ADR-084) | 0.12.0 | an SDK reader half |
| `@QueryParam` | `ActionParamMetadata.bindingSource`, `queryKey` | the HTTP layer | J5 + S4 | — |
| `@NavMenu` | `DomainMetadata.navMenu` | none needed | J5 + S4 | — |
| `@Tab` | `UIMetadata.tabs` | none needed | J5 + S4 | — |
| `@Encrypted`, `@RowLevelSecurity` | none | none | not in 0.11.0 | exeris-kernel#585, then exeris-sdk#165 |
| `@GraphQuery` | `GraphMetadata.queries` | none | not in 0.11.0 | a decision |

Every row that starts an extraction deletes the annotation's `UNREAD_NOTES` or `INERT_ANNOTATIONS`
entry in the same change, so `-Aexeris.strict` never reports as unread an annotation whose
component reaches emitted output.

## Not in 0.11.0

- **`@Channel`** (J4, S3): SDK 0.13 has no `-io` reader half for `DomainMetadata.channel`, and the
  kernel's WebSocket SPI is preview. Both rows move whole to 0.12.0 with the `@Channel` message-shape
  RFC/ADR: the WebSocket endpoint over kernel ADR-084, the frame types, and how the T53 route
  policy applies to the upgrade request.
- **Generated integration tests beyond the first slice** (#408): PostgreSQL and tenant scopes, 0.12.0.
- **`@Encrypted` / `@RowLevelSecurity`** (C2): the kernel rules first (exeris-kernel#585), then the
  SDK adds carriers (exeris-sdk#165).
- **`@GraphQuery`**: it declares a `cypher` string, and the kernel's graph SPI is dialect-neutral by
  design: `GraphDialect` keeps SQL/PGQ and Cypher out of the caller's sight, and `GraphSession`
  offers traversal and shortest path, with no named-query entry point. Either the kernel adds a named
  query that a dialect resolves, or the SDK replaces the Cypher string with a dialect-neutral
  declaration. Placed once that is decided.
- The rest of the 22: `@Projection`, `@EventHandler`, `@Derived`, `@Rule`, `@Rules` (design-gated on
  the behavioural corpus); `@SagaTransition`, `@SagaTransitions` (exeris-kernel#582); `@Schedule`
  (1.0); `@EventSourced` (EV2); `@InternalApi` (no emitter gates on it); `@RouteAccess` (0.10.0 T53).

## The cut

**Criterion:** A1, JB1–JB4, J1–J3, J5–J10, S1, S2, S4–S6 (without the stretch items), S8 and
T1–T6 are closed; the TCK binding's `unsupportedFacets()` is empty; `contract-coverage.ts` reports
0 GAP; or each open item has moved to a named milestone with its ROADMAP entry. J4, S3 and the S6
stretch items carry a 0.12.0 milestone. A row whose SDK half is not in a final SDK 0.13.x moves
whole to 0.12.0. So does a row whose wave 0 ADR is not accepted when its implementation would start.
A row never ships its extraction without the reader half.

**Sequence:** as in the 0.10.0 plan: final pins, the release PR (which assembles
`docs/migration/0.11.0/` with `tools/migration/assemble-migration.py --release 0.11.0`), a dry run
of `release.yml` from `main`, the tag,
Central, npm, then `0.12.0-SNAPSHOT`.
