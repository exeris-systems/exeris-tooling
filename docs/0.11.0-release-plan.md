# 0.11.0 release plan

0.11.0 has no date; its scope closes it. **Bring the SDK annotations whose carrier exists to emitted
output: `@PrimaryKey`, `@GraphProperty`, `@UIGroup`, `@Blob` and `@Channel`. Do the same for
`@QueryParam`, `@NavMenu` and `@Tab` once the SDK adds their carriers.** Each needs an SDK 0.13
half, which 0.10.0 does not wait for, so this is the release that pins SDK 0.13. The
[ROADMAP](../ROADMAP.md) "0.11.0" section keeps the checklist and points here. This note holds the
order, the gate on each item and the Java/TS pairing, in the shape of the
[0.10.0 plan](0.10.0-release-plan.md).

**Pins.** 0.11.0 pairs with SDK 0.13, final on Maven Central before the cut, carrying
exeris-sdk#187 (the `-io` reader half for the five extractions) and exeris-sdk#186 (carriers for
`@QueryParam`, `@NavMenu`, `@Tab`). The kernel pin is whatever 0.10.0 shipped on, unless a row below
needs more. No cross-repo SNAPSHOT at the cut (Versioning policy).

## Why every row waits on the SDK

Two different SDK halves gate these annotations, and every extraction needs at least one:

- **A carrier** — an AST component the processor can write. `@QueryParam`, `@NavMenu` and `@Tab` have
  none (exeris-sdk#186).
- **The reader half** — ADR-042 requires the SDK's `-io` `SourceModelReader` to read what the
  processor writes, in the same release, or the two producers diverge and a round-trip caller
  reads the dropped facet as a user edit. The reader reads none of the five whose carrier exists
  (exeris-sdk#187). It is the rule 0.10.0's J3 applies to `@RouteAccess` and exeris-sdk#161.

So no row writes its component until the SDK pin carries both halves. What needs no SDK is the
decision work, wave 0, and it can run during 0.10.0.

**Gate vocabulary:** as in the 0.10.0 plan — **none**, **RFC/ADR** (number reserved in
`exeris-docs/adr-index.md` and on `main` before the content), **upstream** (a kernel or SDK issue;
the row enters only if that half is final before the cut).

## Wave 0 — decisions (no SDK gate; may start during 0.10.0)

- [ ] **`@Blob` route shape** — RFC, then ADR: the upload and download routes, how a `@Blob` field
      appears in the entity DTO, and the refusal on a `dataScope = GLOBAL` entity.
- [ ] **`@Channel` message shape** — RFC, then ADR: the WebSocket endpoint over kernel ADR-084, the
      frame types, and how 0.10.0's T53 route policy applies to the upgrade request.
- [ ] **Graph property encoding** — a kernel ask. `GraphSession.upsertNode` takes an encoded
      `LoanedBuffer`, the SPI names no encoding ("e.g. MessagePack or raw JSON"), and the Community
      driver decodes UTF-8 JSON. Emitted code must not bind to one driver's choice, so the SPI
      states the encoding, or the J2 PR records the assumption and the reason.
- [ ] **`@GraphQuery`** — a decision between the kernel and the SDK (see *Not in 0.11.0*).

## Annotation coverage

Of the 54 SDK annotation types, 22 reach no emitted output on either side: 19 the processor never
reads, and three it reads without any generator emitting from them (`@EventSourced`, `@InternalApi`,
`@RouteAccess`). `EXTRACTED_ANNOTATIONS`, `INERT_ANNOTATIONS` and `UNREAD_NOTES` in
`ExerisDomainProcessor`, and `contract-coverage.ts` on the TS side, are the authority for those
counts. The table covers eleven of the 22: eight are placed in 0.11.0 and three are not.

| Annotation | SDK carrier | Kernel contract | Wave | Waits on |
| --- | --- | --- | --- | --- |
| `@PrimaryKey` | `SystemFieldsMetadata.primaryKeyField` | none needed | J1 | exeris-sdk#187 |
| `@GraphProperty` | `GraphMetadata.properties` | `GraphSession.upsertNode` | J2 | exeris-sdk#187; the encoding |
| `@UIGroup` | `UIMetadata.groups` | none needed | J2 + S1 | exeris-sdk#187 |
| `@Blob` | `FieldMetadata.blob` | `storage` subsystem, `BLOB_STORE` | J3 + S2 | RFC/ADR; exeris-sdk#187 |
| `@Channel` | `DomainMetadata.channel` | `WebSocketProvider` (kernel ADR-084) | J4 + S3 | RFC/ADR; exeris-sdk#187 |
| `@QueryParam` | none | the HTTP layer | J5 + S4 | exeris-sdk#186 |
| `@NavMenu` | none | none needed | S4 | exeris-sdk#186 |
| `@Tab` | none | none needed | S4 | exeris-sdk#186 |
| `@Encrypted`, `@RowLevelSecurity` | none | none | not in 0.11.0 | exeris-kernel#585, then exeris-sdk#165 |
| `@GraphQuery` | `GraphMetadata.queries` | none | not in 0.11.0 | a decision |

Every row that starts an extraction deletes the annotation's `UNREAD_NOTES` or `INERT_ANNOTATIONS`
entry in the same change, so `-Aexeris.strict` never reports as unread an annotation whose
component reaches emitted output.

## Not in 0.11.0

- **`@Encrypted` / `@RowLevelSecurity`** (C2): the kernel rules first (exeris-kernel#585), then the
  SDK adds carriers (exeris-sdk#165).
- **`@GraphQuery`**: it declares a `cypher` string, and the kernel's graph SPI is dialect-neutral by
  design: `GraphDialect` keeps SQL/PGQ and Cypher out of the caller's sight, and `GraphSession`
  offers traversal and shortest path, with no named-query entry point. Either the kernel adds a named
  query that a dialect resolves, or the SDK replaces the Cypher string with a dialect-neutral
  declaration. Placed once that is decided.
- The rest of the 22: `@Projection`, `@EventHandler`, `@Derived`, `@Rule`, `@Rules` (design-gated on
  the behavioural corpus); `@SagaTransition`, `@SagaTransitions` (exeris-kernel#582); `@Schedule`
  (1.0); `@EventSourced` (EV2); `@InternalApi` (no emitter gates on it); `@RouteAccess` (0.10.0 T53).

## The cut

**Criterion:** J1–J5 and S1–S4 are closed, or each open item has moved to a named milestone with its
ROADMAP entry. A row whose SDK half is not in a final SDK 0.13 moves whole to 0.12.0. So does a row
whose wave 0 ADR is not accepted when its implementation would start. A row never ships its
extraction without the reader half.

**Sequence:** as in the 0.10.0 plan: final pins, the release PR (which assembles
`docs/migration/0.11.0/` with `tools/migration/assemble-migration.py --release 0.11.0`), the tag,
Central, npm, then `0.12.0-SNAPSHOT`.
