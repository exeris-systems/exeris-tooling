### `exeris-codegen-ts`: view routes, navigation and prerendered paths are in files the generator rewrites on every run

With `scaffold: true`, the entity routes, the view routes, the sidebar and the prerendered paths are no longer written into the seeds `app.routes.ts`, `app.component.ts` and `app.routes.server.ts`. Three files the generator rewrites on every run hold them, and the seeds import and compose those files:

| File | Class | Holds |
|:--|:--|:--|
| `src/app/app.routes.generated.ts` | owned | `generatedRoutes`: one empty-path route whose component is `AppShellComponent` and whose children are the entity routes (with their `canActivate`) and the view routes; `notFoundRoutes`, an empty array in this release |
| `src/app/shell/app-shell.component.ts` | owned | `AppShellComponent`: the header, the sidebar, and the `<main>` that holds the router outlet |
| `src/app/app.routes.server.generated.ts` | owned, `render: 'ssg'` only | `generatedServerRoutes`: the prerendered view paths |
| `src/app/app.routes.ts` | seed | the landing redirect, `...generatedRoutes`, your own routes, `...notFoundRoutes` |
| `src/app/app.routes.server.ts` | seed, `render: 'ssg'` only | the root `Prerender` entry when the app has a redirect, `...generatedServerRoutes`, the `**` `Client` entry |
| `src/app/app.component.ts` | seed | `<router-outlet />` |

The owned files are in the manifest, so a view added to the metadata, or removed from it, changes them on the next run without `--overwrite`, and a file the run stops producing is pruned. The seeds are kept as they are.

An app generated by 0.11 keeps the seeds it has. It still builds and still routes the views it had, but a view added after the upgrade gets no route, no sidebar link and no prerendered page until its seeds import the owned files. The run says so when it keeps an `app.routes.ts` that does not import `app.routes.generated`:

```text
src/app/app.routes.ts was kept and does not import app.routes.generated.
```

To take the new shape, edit the seeds by hand. A 0.11 `app.routes.ts`, here the one `node scripts/gen-sample-app.mjs <dir> --ssg` writes, with four `@View` pages:

```ts
import { Routes } from '@angular/router';
import { aboutRoutes } from './pages/about.route';
import { footerRoutes } from './pages/footer.route';
import { homeRoutes } from './pages/home.route';
import { postRoutes } from './pages/post.route';

export const routes: Routes = [
  {
    path: '',
    redirectTo: 'about-us',
    pathMatch: 'full'
  },
  ...aboutRoutes,
  ...footerRoutes,
  ...homeRoutes,
  ...postRoutes,
];
```

becomes, in 0.12:

```ts
import { Routes } from '@angular/router';

import { generatedRoutes, notFoundRoutes } from './app.routes.generated';

export const routes: Routes = [
  {
    path: '',
    redirectTo: 'about-us',
    pathMatch: 'full'
  },
  ...generatedRoutes,
  // Routes of your own go here, before notFoundRoutes.
  ...notFoundRoutes,
];
```

1. In `app.routes.ts`, delete the imports of `./pages/*.route`, the guard import from `./core/route-guards` and every entity route and view spread the generator wrote, add the import of `generatedRoutes` and `notFoundRoutes`, and put `...generatedRoutes` where the generated routes were. Keep the redirect and any route you added yourself; a route of your own goes before `...notFoundRoutes`.
2. Replace `app.component.ts` in the same change. The sidebar and the `<main>` now live in `AppShellComponent`, a parent of the generated routes: an `app.component.ts` that still renders its own header, sidebar and `<main>` around the outlet shows them twice. Its template becomes:

   ```ts
   import { ChangeDetectionStrategy, Component } from '@angular/core';
   import { RouterOutlet } from '@angular/router';

   @Component({
     selector: 'app-root',
     standalone: true,
     changeDetection: ChangeDetectionStrategy.OnPush,
     imports: [RouterOutlet],
     template: `<router-outlet />`,
   })
   export class AppComponent {
     title = 'Exeris Foundation';
   }
   ```

   Edits made by hand to the sidebar or the header have no place in a seed any more: `shell/app-shell.component.ts` is rewritten on every run. Take the navigation from `@NavMenu`, and put anything else around the outlet in your own components.
3. Under `render: 'ssg'`, replace the prerender entries in `app.routes.server.ts` with `...generatedServerRoutes`, keeping the root entry and the `**` entry:

   ```ts
   import { RenderMode, ServerRoute } from '@angular/ssr';

   import { generatedServerRoutes } from './app.routes.server.generated';

   export const serverRoutes: ServerRoute[] = [
     { path: '', renderMode: RenderMode.Prerender },
     ...generatedServerRoutes,
     { path: '**', renderMode: RenderMode.Client },
   ];
   ```

   A `getPrerenderParams` entry you added for a parameterised route stays in this seed, before `{ path: '**' }`.

Regenerating into a fresh directory and comparing the three seeds is the quickest way to see the target. `--overwrite` also replaces them, with the loss of every edit made to them.

This does not apply with `scaffold: false`: no seed is written, `view.routes.ts` and `view.routes.server.ts` keep their shape, and the app's own routes file imports them as before. It does not change which views are routed in this release: every view with a route is in `generatedRoutes`, as it was in the seed, and the not-found route, the layout shell and the single `<main>` per page are not part of it.
