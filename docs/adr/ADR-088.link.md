# ADR-088 — Cryptographic License Manifest Format and Offline Verification (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-088-cryptographic-license-manifest-and-offline-verification.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-088-cryptographic-license-manifest-and-offline-verification.md)

ADR-088 is a cross-repo decision owned by `exeris-docs`, binding `exeris-kernel` and this
repository. It fixes the `license-manifest.json` format: JSON schema v1, canonicalized with
RFC 8785 (JCS) and signed with Ed25519, verified offline in Phase 0 of the kernel bootstrap against
keys pinned in the kernel's `TrustedIssuerKeyStore`.

## What it asks of exeris-tooling

- **The signing side.** An `exeris-manifest-tool` CLI module that reads commercial entitlement
  YAML, canonicalizes it with RFC 8785 and signs it with an Ed25519 private key. The kernel only
  verifies; producing a signed manifest is this repository's job.
- **A canonicalizer that agrees with the kernel's.** RFC 8785 canonicalization, implemented
  without a third-party JSON library. A signature is computed over the canonical bytes, so a
  canonicalizer here that differs from the kernel's by one byte on any input yields manifests the
  kernel rejects.
- **Standard JDK cryptography only:** `java.security.Signature.getInstance("Ed25519")`.

None of this exists in the repository yet.

## When to consult ADR-088 from exeris-tooling

- Adding the manifest CLI, or any code that canonicalizes, signs or verifies a license manifest.
- Any change to what a release build stamps into, or reads from, a production artifact.
